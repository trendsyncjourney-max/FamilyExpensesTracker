# Hearth Development Guide

## Architecture

Hearth is a single Node.js application with two halves sharing one repo:

- **Client** (`src/`) — React 19 SPA built by Vite. Talks to the API through
  a typed tRPC client (`@trpc/react-query` + TanStack Query). Styling with
  Tailwind CSS and shadcn/ui components (`src/components/ui/`, configured in
  `components.json`).
- **Server** (`api/`) — Hono app (`api/boot.ts`) that mounts the tRPC
  handler at `/api/trpc` and serves the built client in production. In dev,
  `@hono/vite-dev-server` runs it inside the Vite process.
- **Shared contracts** (`contracts/`) — types, constants and error codes
  imported by both sides (aliased as `@contracts/*`).

Request flow: page component → tRPC React hook → Hono → tRPC middleware
(auth/role) → domain router → query helper (`api/queries/*`) → Drizzle ORM →
MySQL. Responses use SuperJSON, so Dates and bigint-safe values round-trip.

### Invariants (important)

- **Money is integer cents** everywhere (`amountCents`). Never use floats.
  Formatting helpers live in `api/lib/money.ts` and are unit-tested.
- **Privacy is enforced server-side.** Every domain row carries `familyId`,
  `scope` (`shared`/`personal`) and `ownerId`. Query helpers filter by all
  three — personal rows are never returned to anyone but their owner.
- **Two-sided clearing.** Reimbursements and advance returns only settle when
  both parties confirm; state transitions go through dedicated procedures
  (`approve`, `markPaid`, `confirmReceived`, …), not free-form updates.
- **Auditability.** State changes insert rows into `audit_events`.

## Data model (`db/schema.ts`)

| Table | Purpose |
| --- | --- |
| `users` | Accounts (unionId from OAuth, role `user`/`admin`) |
| `families` | Households; invite code, currency, advance-aging warning days |
| `family_memberships` | User↔family join with role (`owner`/`member`) |
| `categories` | Per-family categories with scope `shared`/`personal`/`both` |
| `expenses` | Core records: status `draft→posted→disputed→resolved→voided`, return status, optional receipt |
| `refunds` | Refund entries linked to an expense (partial/full) |
| `reimbursement_requests` + `reimbursement_items` | Settlement requests across shared expenses, two-sided confirm |
| `advance_requests` + `advance_returns` | Cash advances, receipt reconciliation, remainder returns |
| `projected_expenses` | Planned one-off / recurring (RRULE) expenses |
| `notifications` | In-app notifications for requests and confirmations |
| `audit_events` | Immutable trail of state changes |

Relations are declared in `db/relations.ts`; migrations live in
`db/migrations/` (generated by drizzle-kit). `db/seed.ts` inserts an
idempotent demo household ("The Ember Household", invite `HEARTHDEMO`).

## API / router map (`api/router.ts`)

All procedures are tRPC; `ping` is public, everything else requires auth.
Domain procedures resolve the caller's family membership server-side.

| Router | Procedures |
| --- | --- |
| `auth` | `me`, `logout` |
| `family` | `current`, `create`, `join`, `updateSettings`, `categories` |
| `category` | `list`, `create`, `update` |
| `expense` | `list`, `listPersonal`, `getById`, `create`, `update`, `transition`, `addRefund`, `setReturnStatus`, `auditTrail` |
| `reimbursement` | `inbox`, `sent`, `getById`, `create`, `approve`, `reject`, `cancel`, `markPaid`, `confirmReceived` |
| `advance` | `inbox`, `sent`, `getById`, `request`, `approve`, `reject`, `cancel`, `disburse`, `reconcile`, `returnRemainder`, `confirmReturn` |
| `projection` | `list`, `create`, `update`, `skip`, `realize` |
| `dashboard` | `summary` |
| `notification` | `list`, `unreadCount`, `markRead`, `markAllRead` |
| `audit` | `list` |

Auth/session plumbing lives in `api/kimi/` (OAuth verify, JWT session via
`jose`, cookies in `api/lib/cookies.ts`). Receipt images go through
S3-compatible storage with presigned URLs (`@aws-sdk/client-s3`).

## Frontend map (`src/pages/`)

`Welcome`/`Login` (unauthed) → `AuthLayout` → tab shell (`Home`, `Records`,
`Requests`, `Calendar`, `Personal`, `More`), plus detail/new pages
(`records/RecordNew`, `records/RecordDetail`, `RequestNew`, `RequestDetail`).
The tRPC client is wired in `src/main.tsx` / providers; `useAuth` exposes the
session. PWA config is in `vite.config.ts` (`vite-plugin-pwa`, Workbox,
autoUpdate).

## Testing

- **Unit tests** run with Vitest: `npm test` (see `api/lib/money.test.ts`).
  Config in `vitest.config.ts`.
- **Type checking:** `npm run check` (`tsc -b` across app/server projects).
- Add tests next to the module they cover (`*.test.ts`). Pure helpers (money,
  dates, status transitions) are the best targets; prefer testing query
  helpers against a schema-mocked boundary.

## Coding conventions

- TypeScript strict, ESM, path aliases `@/*` (src) and `@contracts/*`.
- Formatting/linting: Prettier (`npm run format`) and ESLint (`npm run lint`).
- shadcn/ui for UI primitives; compose rather than restyle.
- Zod schemas validate all tRPC inputs (`moneyCents`, `YYYY-MM-DD` dates…).
- Dates: ISO `YYYY-MM-DD` strings for expense dates; RRULE for recurrence.
- Keep privacy filtering in `api/queries/*` — never scope-filter in React.

## Common tasks

| Task | How |
| --- | --- |
| Add a column/table | Edit `db/schema.ts` (+ `relations.ts`), `npm run db:generate`, `npm run db:push`, update seed if demo-relevant |
| Add an endpoint | Add a procedure to the right router in `api/`, with a Zod input schema and a query helper in `api/queries/` |
| Add a page | Create `src/pages/…`, register the route in `src/App.tsx`, add nav entry in `Layout`/`MobileTabBar` if needed |
| Reset demo data | Delete rows for invite `HEARTHDEMO` (or use a fresh DB) and re-run `npx tsx db/seed.ts` |
| Test the PWA | `npm run build && npm run preview` — service worker is off in dev |
| Verify before PR | `npm run check && npm run lint && npm test && npm run build` |
